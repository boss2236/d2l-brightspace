Connect your AI

Your Brightspace data (announcements, grades, deadlines, and the text of lecture notes) can be connected to any AI that supports MCP, and to any app or n8n workflow through a small REST API. Both read the local database that d2l sync keeps up to date, so no AI ever talks to Brightspace directly, and everything is read-only.

How it fits

Brightspace
    │  d2l sync (3× a day, read-only)
    ▼
data/d2l.db ──┬─▶ d2l mcp     stdio  → Claude Code, Gemini, Copilot, Codex…
              ├─▶ d2l serve   :8765  → /mcp + /api/*  → n8n, apps, web AIs
              └─▶ notify             → desktop, Telegram, Discord, webhook

stdio is the easiest option. The AI app starts d2l mcp by itself, so there's no server to keep running and no token. Use HTTP when something can't start a local program, like n8n, a phone app, or a web AI.

Claude Code

Register the server once for your user account, so every project can use it:

claude mcp add -s user brightspace -- uv run --directory /path/to/d2l-brightspace d2l mcp

Check it with claude mcp list. Inside Claude Code, /mcp shows the tools. Typing /mcp__brightspace__week_ahead runs the built-in weekly-plan prompt.

Gemini CLI

Add this to ~/.gemini/settings.json and merge it with anything already in mcpServers:

{
  "mcpServers": {
    "brightspace": {
      "command": "uv",
      "args": ["run", "--directory", "/path/to/d2l-brightspace", "d2l", "mcp"]
    }
  }
}

Or run gemini mcp add -s user brightspace uv -- run --directory /path/to/d2l-brightspace d2l mcp. Check with /mcp inside Gemini.

Claude Desktop, Cursor, Windsurf, LM Studio and others

Most desktop apps use the same mcpServers JSON: Claude Desktop's claude_desktop_config.json, Cursor's ~/.cursor/mcp.json, LM Studio's mcp.json.

{
  "mcpServers": {
    "brightspace": {
      "command": "uv",
      "args": ["run", "--directory", "/path/to/d2l-brightspace", "d2l", "mcp"]
    }
  }
}

If an app can't find uv, use its full path (which uv on Linux/macOS, where uv on Windows). Replace /path/to/d2l-brightspace everywhere with the folder you cloned this into. The app's Connect AI tab fills in the real path for you with its Add buttons.

ChatGPT, claude.ai and other web AIs

Web AIs run in the cloud and can't reach 127.0.0.1, so they need a public link to this laptop. Open Brightspace from your launcher (or http://127.0.0.1:8766) → Connect AI and pick one of these:

ModeWhenWhat you do
Quick linkNo setup, try it nowPress Use quick link. It's free and needs no account, but it's slower and gets a new address on every restart, so you re-copy it into the connector.
My Cloudflare tunnelYou have a domain on Cloudflare and want a fixed, faster address Zero Trust → Networks → Tunnels → Create a tunnel (Cloudflared). Copy the token from the install command; you don't need to run it. Add a public hostname (e.g. brightspace.yourdomain.com) with service HTTP → localhost:8765. Paste the hostname and token in the app. The app runs and supervises the tunnel.
My own URL / IPYou already expose this machine: own reverse proxy, a public IP with port forwarding, ngrok, Tailscale Funnel, your own cloudflared config… Point it at http://localhost:8765 and enter the public address. For a public IP or a proxy on another machine, tick Open a direct port (default 8767) and forward that port to this laptop.

Then press Copy and add the link in the AI:

  1. claude.ai: Settings → Connectors → Add custom connector. Name it Brightspace, paste the link, leave OAuth empty, then enable it in a chat from the tools menu.
  2. ChatGPT: Settings → Apps & Connectors → Advanced → Developer mode on → Create. Paste the link and set authentication to None.

Is it working? Every minute the app calls the public link from outside, checking the address the way the internet sees it rather than through this laptop's DNS cache. It confirms the answer comes from this app and that a real MCP call gets through. The Connect AI tab then shows either ✓ Reachable or what's wrong: DNS not resolving, connection refused, TLS certificate, tunnel up but not reaching the laptop (502/530), a proxy rewriting the Host header, or a Cloudflare token that's been rejected.

The secret in the link is the only lock: anyone who has it can read your courses and grades. Claude.ai and ChatGPT require https with a valid certificate, so a plain http:// IP only suits n8n and your own apps. The control page (port 8766) is never exposed; tunnels and the direct port only reach the token-gated MCP/REST port. To rotate the secret, delete D2L_API_TOKEN from .env and restart the app.

n8n, custom apps and WhatsApp

Pull (n8n reads from you): an HTTP Request node calls GET http://127.0.0.1:8765/api/deadlines?days=7 with Header Auth Authorization: Bearer <token>. If n8n runs in Docker, use host.docker.internal and start the server with serve --host 0.0.0.0.

Push (every sync sends changes to n8n): create a Webhook trigger in n8n and put its URL in .env:

D2L_WEBHOOK_URL=http://localhost:5678/webhook/brightspace

Each sync POSTs a JSON batch like this:

{"source": "d2l", "events": [
  {"kind": "new_announcement", "course": "CHEM1010 General Chemistry I", "summary": "Quiz 1 reminder",
   "detail": "A gentle reminder that…", "url": "https://d2l.udst.edu.qa/…", "ts": "2026-09-18T11:56:50+00:00"}
]}

From there, n8n can forward to WhatsApp (WhatsApp Business Cloud node or Twilio), email, Notion, Google Calendar, or an AI agent node that has the Brightspace MCP as a tool. Event kinds: new_announcement, new_grade, grade_changed, new_assignment, due_changed, new_quiz, new_files, due_soon, session_expired.

Telegram and Discord are built in, so they don't need n8n. See .env.example.

ToolUse

list_courses / sync_statusWhat's there and how fresh it is
